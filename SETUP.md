# Telegram-бот для получения кодов Rockstar (с проверкой заказа GGsel)

## Быстрый старт

### 1. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 2. Настройка .env

Скопируй `.env.example` → `.env` и заполни:

```env
BOT_TOKEN=токен_от_BotFather
ADMIN_IDS=твой_telegram_id

IMAP_EMAIL=почта_с_которой_бот_читает_коды
IMAP_PASSWORD=пароль_приложения_от_этой_почты

TELEGRAM_PROXY=   # только если сервер в РФ, см. ниже
GGSEL_SELLER_ID=твой_id_продавца
GGSEL_API_KEY=твой_api_ключ
```

`.env` никогда не должен попадать в git (уже в `.gitignore`).

### 3. GGsel / Digiseller API

1. ID продавца: https://my.digiseller.com/inside/my_info.asp
2. API-ключ: https://my.digiseller.com/inside/api_keys.asp
3. Перед боевым запуском проверь интеграцию на реальном номере заказа:
   ```bash
   python check_ggsel.py <номер_заказа>
   ```
   Скрипт печатает сырой ответ API. Если поле с ID товара называется не так,
   как в списке `_PRODUCT_ID_FIELDS` в `ggsel.py` — допиши его туда.

### 4. Прокси до Telegram (только если сервер в РФ)

Bot API у Telegram в РФ часто нестабилен напрямую. Раньше здесь стоял Tor
(`socks5://127.0.0.1:9050`) — он и был главной причиной постоянных обрывов
(нестабильные цепочки, забаненные exit-ноды). Сейчас прокси настраивается
через `TELEGRAM_PROXY` в `.env` и код от него не зависит жёстко.

Более надёжный вариант, чем Tor: свой SOCKS5-прокси (например, `microsocks`
или `3proxy`) на недорогом VPS за рубежом (Нидерланды/Финляндия), который сам
работает под systemd с `Restart=always`. Тогда `TELEGRAM_PROXY` — это адрес
именно этого прокси-сервера, а не Tor.

### 5. Запуск бота

```bash
python bot.py
```

### 6. Добавление почты и товара (через админку)

1. Напиши боту `/admin`
2. → Управление почтами → Добавить почту
3. Введи email общего ящика
4. Введи ID товара GGsel/Digiseller, который должен соответствовать этой почте

Теперь при запросе кода пользователь сначала вводит номер своего заказа —
бот проверяет через API, что заказ существует, оплачен и относится к нужному
товару, и только после этого разрешает ждать код. Один номер заказа можно
использовать только один раз.

## Структура проекта

```
tg_code_bot/
├── bot.py              # точка входа
├── config.py           # конфиг из .env
├── database.py         # SQLite: все таблицы и запросы
├── imap_client.py      # IMAP polling (чтение писем с кодами)
├── ggsel.py            # клиент GGsel/Digiseller API (проверка заказа)
├── check_ggsel.py       # диагностика: сырой ответ API по номеру заказа
├── keyboards.py        # inline-клавиатуры
├── states.py            # FSM состояния
├── handlers/
│   ├── user.py          # главное меню, мои почты, запрос кода + проверка заказа
│   └── admin.py          # /admin панель
├── .env.example
├── requirements.txt
└── SETUP.md
```

## Требования

- Python 3.10+
- Общий почтовый ящик (IMAP) с письмами кодов
- API-ключ продавца GGsel/Digiseller
